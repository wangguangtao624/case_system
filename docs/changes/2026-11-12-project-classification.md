# v2.6.4-dev.1 · 测试类型与芯片分组工作台

开发分支：`dev/v2.6.4`。基于 v2.6.3，与 `main` 独立维护；当前为开发验收版本。

开发工作区：`workspaces/v2.6.3`，开发入口 http://10.26.10.38:5000/dashboard 。

## 项目结构

项目增加 `test_type`（firmware/chip/tool）、`chip_model`、`firmware_version`。

- 固件测试：所属芯片 + 固件版本，按芯片分组。MAT130 V300 V4.2.5_DVP 对应芯片 MAT130V300。
- 芯片功能测试：所属芯片，无固件版本。MAT821、MAT130V300 均可以建立芯片功能测试项目。
- 工具测试：独立分类，不要求芯片和固件版本。

三类测试继续复用项目 → 模块 → 用例的数据关系、字段、分配、执行、附件、导入导出和报告流程。芯片分组为展示结构，不会改变项目 ID 或用例归属。

## 使用流程

1. 在工作台或左侧目录点击新建项目，选择测试类型。
2. 填写项目名称。识别出的芯片/版本可通过“填入建议”采用，也可以独立填写。
3. 所属芯片支持复用已有型号。型号统一去除空格、转成大写。
4. 新建后进入未发布范围，导入或建立测试用例，沿用原有发布流程。
5. 点击项目卡片右上角设置，或目录项目的“···”，调整类型、芯片、版本。
6. 工作台和目录同步切换类型；工作台可继续搜索名称/版本和筛选芯片。项目看板使用当前测试类型，默认展示进行中的已发布项目。

项目状态（未发布/进行中/归档）与测试类型为两个独立维度；项目数量和统计遵循当前状态、执行者范围。

## 历史数据兼容

首次打开数据库时，事务内添加分类字段并提取名称中可识别的芯片及固件版本。所有历史项目默认保留为固件测试，不依据无版本名称擅自改变业务类型。无法识别芯片的项目显示在“待分类芯片”，允许管理者通过项目设置调整。

迁移仅执行一次，重启不会覆盖人工分类。既有项目名、ID、状态、用例、执行记录和附件关系保持不变。生产环境与生产数据未更改。
